# 启动期自动终端账号注册安全验证

验证日期：2026-11-08。结论：**本轮安全门未通过，不恢复启动期或运行期自动建号。** 当前实现继续只读发现用户在宿主中预置的终端账号，不增删宿主账号字典。

## 1. 要验证的问题

将内存账号创建限制为启动时一次，是否足以避免与现有账号读者并发？

必须区分宿主串行调用插件回调，与插件自己创建的后台线程。前者串行不代表后者已停止，也不代表同一账号字典没有存活的迭代器。一次 `setdefault` 不覆盖现有键，但仍可能改变字典大小并使既有迭代器失效。

## 2. 实测环境与范围

- Python 3.11.17；OlivOS 1.0.0 / SVN 300 / compatible SVN 190。
- 已有镜像：`sha256:d13535da23028b8258fa5816165d9499efc5cf80f2f1ec9d1b6186cfc8719f51`。
- 容器关闭外网、根文件系统只读，仅 `/tmp` 为临时可写目录；内存 384 MiB、CPU 2、PID 上限 64。
- 使用真实 `OlivOS.pluginAPI.shallow` 的 `load_plugin_list`、`check_plugin_list` 和 `run_plugin_func(None, 'init_after')`。
- 加载两个专用的解包测试插件，不安装到真实部署，不读取真实账号或凭据，不修改 Cockpit 源码来插入测试账号。
- **该镜像不是参考基线 1.0.2-beta.3 / c6a99fc2a3b4，不能作为该基线的运行验收。**

## 3. 单次注册对照

两个分组使用相同初态：加载器持有一个测试账号，缺少合格终端账号。

1. 较早插件在真实 `init` 回调中启动 daemon 读线程。
2. 读线程取得 `Proc.Proc_data['bot_info_dict']` 的真实迭代器，消费首项并保留迭代器，随后用 Event 暂停。插件回调确认读线程已经就绪后返回。
3. 另一插件在真实 `init_after` 回调中构造原生 `bot_info_T`。两组都执行构造，唯一注册变量如下：
   - 控制组不修改字典。
   - 处理组调用一次 `data.setdefault(candidate.hash, candidate)`。
4. 放行原读线程，对同一迭代器调用 `next()`。读线程捕获并记录异常，异常没有逃逸到测试宿主。

Event 只用于测试插件的同步，不替换宿主字典、不修改宿主指令，也没有在 membership/getitem 之间插入 trace、property 或 sleep。

### 实际结果

| 分组 | 本阶段插入次数 | 同一字典的大小 | 原迭代器下一次读取 |
|---|---:|---|---|
| 控制组 | 0 | 1 → 1 | 正常 `StopIteration` |
| 处理组 | 1 | 1 → 2 | `RuntimeError: dictionary changed size during iteration` |

两个分组均由独立 Python 进程执行，避免插件模块缓存或前一分组状态污染。两组都确认读线程结束、没有其他未捕获异常，且读者始终持有加载器中的同一个字典。

另有较早的多阶段探针也观察到相同错误；上表使用的是进一步收缩后的单阶段、同初态对照，不以早期多阶段计数代替最终结果。

## 4. 判读

实测证明：**`init_after` 不是能保护任意较早插件后台账号读者的通用注册安全点。** 将插入从配置线程移到这个回调，或把插入次数减为一次，都不足以解决该反例。

本轮没有验证出可用于默认恢复自动注册的可靠启动边界，也没有找到已经核实、能协调这些既存读者的宿主注册机制。因此按“先验证安全，再恢复”的条件，自动创建继续暂缓。

这不是以下结论：

- 不是所有宿主版本都会在一次注册后出错。
- 不是已经观察到真实 nativeWinUI 或加载器内部线程崩溃。
- 不是完整 `run_total`、真实适配器、GUI 或未知插件生态的验收。
- 不是对所有 `init` 时序的排除证明；未证明某个时序失败也不能当作该时序已安全。
- 不使用“nativeWinUI 与加载器共享同一活字典”的旧论据，也不从源码两行查找语句推断 CPython 中必然可发生线程切换。

测试捕获到的是一个合法启动读者受到一次插入影响的反例；它足以否定“只要启动时注册一次就天然安全”的通用承诺，不用于估算线上发生率。

## 5. 当前行为与重新评估条件

当前终端仍按 [reference.md](reference.md) 的用户预置契约运行：优先只读选择合格的 `terminal_link / terminal / default` 账号，没有则明确停用并等待只读重选。没有新增自动建号开关，没有恢复 `terminal_bot_id` 或 `memory_created`，也不自动写账号配置、重启宿主或清理账号。

若未来重新评估自动创建，须先明确并验证注册方与相关读者共同遵守的协调契约，例如宿主提供的受控注册能力，或能够证明早于相关插件代码及并发读者的启动接缝。不能仅凭回调名称、优先级、线程枚举或 Cockpit 私有锁认定安全；届时还需独立确认对现行零增删契约的变更。
